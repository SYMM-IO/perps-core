## Standards

No hard documented-standard violation was identified. AccountLayer and InstantLayer append mappings; core settlement metadata uses a separate namespace. The deployment manifest includes the new batch-facet implementation-library dependency. Semantic ABI review found expected additive getters/errors and no removed entries.

One optional maintenance finding: template insertion authorization in `contracts/instantLayer/facets/Execution/ExecutionFacet.sol:394-396` repeats ordinary flex-fill authorization at lines 440-444. A shared predicate could reduce future drift. This is a judgment call, with no demonstrated authorization bypass. The forwarding `openPositionState` function is justified by the contract size constraint.

Standards result: zero hard violations; one optional duplication finding.

## Spec

No additional concrete correctness or security regression was confirmed in the inspected remediation paths. There are two evidence/closure gaps and one economic scope decision:

1. **Historical and deployment closure is separate work.** The branch explicitly excludes deployment, role mutation, and balance reconciliation. Existing malformed quotes, pre-upgrade liquidation buckets, old ownership transfers, new selectors, and relayer configuration need their own recorded outcomes.
2. **The evidence identifies different F-009 implementations.** The attachment and published branch describe settlement-bucket capture; the local follow-up snapshots all connected PartyBs at liquidation admission. Capture at bucket creation leaves a window for switching mode after admission and before position processing. Use and review the later commit.
3. **OVERDUE netting changes economic behavior.** The branch aggregates quote PnL including funding per PartyB and haircuts negative net buckets. This is documented in the remediation but extends beyond the F-009 bucket fix. [SYM-1525](https://symmio-vibe.atlassian.net/browse/SYM-1525) says to keep quote-level liquidation-loss semantics unchanged; [SYM-1526](https://symmio-vibe.atlassian.net/browse/SYM-1526) plans future cross-mode boundaries. Core and Muon maintainers must explicitly reconcile that requirement with this change. Treat this as a compatibility decision, not a newly proven exploit.

F-007's exact signed flex-field permissions protect the audit's calldata invariant without requiring template IDs in the EIP-712 type. F-008's completion guard implements the audit's alternative of rejecting unfinished atomic opens. F-013 documents retained timelocks, which the original recommendation allowed as a semantic decision.

Spec result: two evidence/closure gaps and one economic scope decision; zero newly confirmed code defects.

## Executable review finding

**R-1: Attach the revert handler before awaiting contract lookup.** In the reviewed branch's `test/parallel/InstantLayerDiamondExecution.test.ts:300-301`, the test creates the reverting `executeTemplate` promise and then awaits `ethers.getContractAt(...)` while evaluating the matcher argument. On this Windows/Node environment, the expected `IncompleteInstantOpen(1)` rejection arrives before the matcher attaches a handler, and Hardhat terminates with an unhandled rejection. This interrupts the security regression run.

Resolve the contract instance before starting the transaction, then pass that instance synchronously to `revertedWithCustomError`. The unmodified suite reproduced the interruption; the single regression passed after this test-only correction in the disposable snapshot. The contract correctly rejected the malformed atomic template. Apply the test correction in the implementation follow-up; the actual fix branch has not been edited by this review.
