Batch Price Array Validation

Oracle-verified batch open and close require one signed market price per quote ID, so a packed Muon signature cannot be reused with a different boundary between the two arrays.

Why the array boundary matters

Muon signs quoteIds followed by prices using packed encoding. Neither array carries a length prefix, so moving the final quote ID into the first price slot leaves the encoded words unchanged:

Payload Quote IDs Prices
Signed batch [q1, q2] [p1, p2]
Repartitioned batch [q1] [q2, p1, p2]

Both encode the words q1, q2, p1, p2. Without a length check, the second payload could verify the same signature while treating q2 as the price of the first quote.

One price for each quote

openPositions and fillCloseRequests now require upnlSig.prices.length == quoteIds.length in the shared Muon verifier. A mismatch reverts with PartyBFacet: Invalid length before timestamp or signature verification. The rejected call changes no quote state and consumes no uPNL counter.

This check applies to the oracle-verified path. Bound-mode batches continue to bypass Muon verification; their ignored oracle payload does not acquire a new price-array requirement.

Keep the existing signing schema

Clients must supply exactly one price for each submitted quote ID, in the same order. The Muon packed hash, TSS signature and gateway signature formats remain unchanged. A correctly formed signed batch needs no schema migration.

The batch facet also replaces two string reverts with the compact custom errors SymbolNotAllowedForPartyA() and DifferentPartyB(). Update error decoding when replacing the facet.
