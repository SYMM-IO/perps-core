Settlement, Pause and Deallocation Guards

Three guards that each close one gap. None changes a signature or a storage slot; each turns a state that should have been impossible into a revert.

Settlement signature index bound

Every quote in a settleUpnl payload names the index of its PartyB in the signed upnlPartyBs list. The bound on that index allowed it to equal the list length, so a payload built with an index one past the end failed on the array read with a panic instead of the intended message. The bound is now strict and such a payload reverts with LibSettlement: Invalid partyBUpnlIndex in signature. No valid payload changes.

Pause on cancelUnbindRequest

All PartyA binding actions are behind whenNotPartyAActionsPaused except the cancellation of a PartyB’s unbind request, which only checked suspension. During a PartyA-actions pause a trader could still cancel its solver’s pending unbind. The cancellation now carries the same pause modifier as the rest of the BindingFacet.

No zeroUpnlDeallocate during liquidation

zeroUpnlDeallocate lets the balance settler role deallocate without a uPNL signature when the account has no open positions and no pending quotes. Between the close that ends a liquidation’s position list and the settlement that finalises it, the account is in exactly that state. A deallocation there would remove the allocation that finalisation consumes to pay the counterparties. The function now carries notLiquidatedPartyA like every other allocation change.
