v0.8.6/Funding

Lazy Accumulated Funding

v0.8.6 stops quote-driven flows from rolling the shared symbol/PartyB accumulated funding state. Per-quote funding is settled lazily from the persisted state, which now changes only when the solver reconfigures rates or epoch duration -- and emits its final state at every such change.

Summary

The accumulated funding system keeps mutable funding state per (symbolId, partyB): a weighted-average rate over completed history plus the rate currently in force. In earlier versions, every quote-driven flow -- position open, close, accumulated funding charge, liquidation sync, migration initialization -- first rolled this shared state forward (re-folding the weighted average and advancing lastUpdatedEpoch) so that a simplified two-term formula could write the quote's accumulatedPaidFunding baseline.

The roll was never required for correctness: the cumulative fee is fully determined by the persisted state at any time (see Lazy Evaluation Model). It only existed to feed that two-term shortcut, and it made the shared state churn at unpredictable points, forced storage writes and logs onto every hot-path quote operation, and added one integer-division rounding per roll.

v0.8.6 removes the roll. Quote-driven flows now compute the quote's baseline with the same lazy formula every read path already used, and never mutate the symbol/PartyB state. The weighted average is re-folded only in the solver configuration paths, which emit the state event after their final storage writes. Between solver updates the persisted funding state is byte-stable.

Lazy Evaluation Model

The persisted state stores the weighted-average rate over completed history (accumulatedRate, valid through lastUpdatedEpoch) and the rate in force since then (currentRate). The cumulative fee per unit of position at any epoch is therefore fully determined without rolling storage: 

currentEpoch  = floor(block.timestamp / epochDuration)
cumulativeFee = snapshotFee
              + accumulatedRate * (lastUpdatedEpoch - startEpoch)
              + currentRate     * (currentEpoch - lastUpdatedEpoch)

Every consumer of the state uses this formula: funding charges, the per-quote accumulatedPaidFunding baseline written at open/close/charge/liquidation/migration, and the aggregate funding debt views. Because the fee charged and the baseline written now come from the same expression, the amount a quote pays equals the change in its recorded baseline exactly, with no re-rounding of the weighted average in between.

What Changed On-Chain

  • LibQuoteFunding.updateAccumulatedPaidFunding no longer calls the accumulated-rate updater. It writes the quote's baseline using the three-term lazy formula above.
  • MigrationFacetImpl._initializeQuoteFunding initializes migrated quotes with the same lazy computation instead of rolling state.
  • LibFundingRate.updateAccumulatedRatesAndEmit was removed; the fold-then-emit pattern only survives inside the solver configuration paths (setEpochDurations, updateAccumulatedFundingFee and the setFundingFee variants).
  • Quote flows no longer pay for symbol-state storage writes or the state log. Settlement amounts are unchanged: the lazy baseline equals the rolled baseline, minus the rounding the roll itself introduced.

State Event

event AccumulatedFundingStateUpdated(
    uint256 indexed symbolId,
    address indexed partyB,
    int256 currentLongRate,
    int256 currentShortRate,
    int256 accumulatedLongRate,
    int256 accumulatedShortRate,
    uint256 lastUpdatedEpoch,
    uint256 lastUpdatedTimeStamp,
    uint256 startEpochTimeStamp,
    uint256 startEpoch,
    uint256 epochDuration,
    int256 snapshotLongFee,
    int256 snapshotShortFee
);

The payload mirrors the persisted FundingFee struct after the state transition has completed. It is emitted after final storage writes in the solver configuration paths -- the only paths that mutate the symbol/PartyB funding state:

  • setEpochDurations
  • updateAccumulatedFundingFee
  • setFundingFee, setLongFundingFee, and setShortFundingFee
