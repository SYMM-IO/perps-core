v0.8.6/Events

Accumulated Funding State Event

v0.8.6 emits the final symbol and PartyB accumulated funding state whenever the new accumulated funding system rolls or reconfigures that state.

Summary

The accumulated funding system keeps mutable funding state per (symbolId, partyB). Before this enhancement, off-chain indexers could see some user intent events, such as funding fee updates, but they could not reliably observe every derived state roll. A quote close, quote funding charge, open-position sync, liquidation sync, or migration initialization can call the shared accumulated-rate updater and change the symbol/PartyB funding rollup.

v0.8.6 adds a dedicated state event for this rollup. The event is about symbol/PartyB funding state only; it does not emit per-quote accumulatedPaidFunding changes.

Event Payload

event AccumulatedFundingStateUpdated(
    uint256 indexed symbolId,
    address indexed partyB,
    int256 currentLongRate,
    int256 currentShortRate,
    int256 accumulatedLongRate,
    int256 accumulatedShortRate,
    uint256 lastUpdatedEpoch,
    uint256 lastUpdatedTimeStamp,
    uint256 startEpochTimeStamp,
    uint256 startEpoch,
    uint256 epochDuration,
    int256 snapshotLongFee,
    int256 snapshotShortFee
);

The payload mirrors the persisted FundingFee struct after the state transition has completed. Consumers can index by symbolId and partyB, then replace their local copy with the emitted fields.

Emission Points

The event is emitted after final storage writes in the direct configuration paths:

  • setEpochDurations
  • updateAccumulatedFundingFee
  • setFundingFee, setLongFundingFee, and setShortFundingFee

It is also emitted by the shared accumulated-rate update path when elapsed epochs actually roll the symbol/PartyB state. That covers quote-driven flows such as position close and accumulated funding charge, plus funding initialization during migration.

Indexer Notes

  • The event is declared in the funding facet ABI for decoding on the core diamond address.
  • Only one log is emitted per changed (symbolId, partyB) state update.
  • Rate setter input events remain useful for intent, but this event is the canonical final-state record.
  • If an accumulated-rate updater is called without a state roll, no state event is emitted from that helper.

Code references: contracts/core/facets/FundingRate/IFundingRateEvents.sol, contracts/core/libraries/LibFundingRate.sol, and contracts/core/libraries/LibQuoteFunding.sol.
