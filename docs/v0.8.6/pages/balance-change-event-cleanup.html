v0.8.6/Events

BalanceChange Event Cleanup

v0.8.6 cleans up liquidation and Clearing House balance events so the emitted type matches the bucket that changed.

Summary

Before v0.8.6, a few liquidation and Clearing House paths either skipped BalanceChangePartyA events or reused generic realized-PnL labels while updating more specific accounting buckets. That made it hard for indexers to tell whether a PartyA credit was reimbursement, a returned fee reserve, deferred balance, or liquidation fee.

v0.8.6 keeps realized PnL events for real PnL movement and uses specific labels for the other buckets. The only new enum value is REIMBURSEMENT_IN; the remaining fixes use existing PLATFORM_FEE_IN, DEFERRED_BALANCE_IN, LF_IN, and LF_OUT labels.

Clearing House Reimbursements

Before: when distributeForClearingHouse paid a liquidating PartyA, the amount was routed into partyAReimbursement, but no BalanceChangePartyA event was emitted at that point. Consumers could only see the later settlement release, which made the reimbursement look like generic balance movement. 

accountLayout.partyAReimbursement[receivers[i]] += amount;
// no BalanceChangePartyA event in the old path

Now: the reimbursement bucket update emits REIMBURSEMENT_IN immediately. PartyB receivers still use BalanceChangePartyB(..., REALIZED_PNL_IN), and non-liquidating PartyA receivers still use REALIZED_PNL_IN. 

accountLayout.partyAReimbursement[receivers[i]] += amount;
emit SharedEvents.BalanceChangePartyA(receivers[i], amount, SharedEvents.BalanceChangeType.REIMBURSEMENT_IN);

Code reference: contracts/core/facets/ClearingHouse/ClearingHouseFacetImpl.sol:181-195.

Released Open Fees

Before: Clearing House pending-quote cleanup released PartyA's reserved open trading fee and added it to partyAReimbursement, but those paths did not emit the fee event. That made released fee reserves look the same as any other reimbursement or later balance release.

Now: when the reserved fee is released into partyAReimbursement, the code emits PLATFORM_FEE_IN. This is used in both the cross-PartyB pending quote cleanup and the PartyA takeover pending quote cleanup. 

uint256 fee = LibQuote.getOpenTradingFee(quote.id);
LibAccount.releaseReservedOpenTradingFee(partyA, fee);
accountLayout.partyAReimbursement[partyA] += fee;
emit SharedEvents.BalanceChangePartyA(partyA, fee, SharedEvents.BalanceChangeType.PLATFORM_FEE_IN);

Code references: contracts/core/facets/ClearingHouse/ClearingHouseFacetImpl.sol:241-245 and contracts/core/facets/ClearingHouse/ClearingHouseFacetImpl.sol:282-285.

Deferred Balance Release

Before: settlePartyATakeover released partyAReimbursement + partyADeferredBalance into PartyA allocated balance and emitted one REALIZED_PNL_IN event for the combined amount. That mixed two different sources and mislabeled deferred balance as realized PnL. 

accountLayout.allocatedBalances[partyA] += totalRelease;
emit SharedEvents.BalanceChangePartyA(partyA, totalRelease, SharedEvents.BalanceChangeType.REALIZED_PNL_IN);

Now: deferred balance release emits DEFERRED_BALANCE_IN. Reimbursement is not emitted again at final release because it was already classified when it entered the reimbursement bucket. 

accountLayout.allocatedBalances[partyA] += totalRelease;
if (deferredBalance > 0) {
    emit SharedEvents.BalanceChangePartyA(partyA, deferredBalance, SharedEvents.BalanceChangeType.DEFERRED_BALANCE_IN);
}

Code references: contracts/core/facets/ClearingHouse/ClearingHouseFacetImpl.sol:483-493 and contracts/core/libraries/liquidation/LibPartyALiquidationProcess.sol:372-376.

Liquidation Fee Events

Before: PartyA liquidation fee settlement emitted only inbound LF_IN events to liquidators. The event stream did not show the matching LF_OUT from the liquidated PartyA, and older settlement split the fee across two liquidator slots.

Now: final settlement emits both sides of the movement: LF_OUT from the liquidated PartyA, then LF_IN to the recorded liquidation starter. 

emit SharedEvents.BalanceChangePartyA(partyA, lf, SharedEvents.BalanceChangeType.LF_OUT);
address liquidationStarter = accountLayout.liquidators[partyA][0];
accountLayout.allocatedBalances[liquidationStarter] += lf;
emit SharedEvents.BalanceChangePartyA(liquidationStarter, lf, SharedEvents.BalanceChangeType.LF_IN);

Code reference: contracts/core/libraries/liquidation/LibPartyALiquidationProcess.sol:379-385.

Enum Compatibility

REIMBURSEMENT_IN is appended after DEFERRED_BALANCE_OUT. Existing integer values keep the same positions, so consumers that decode BalanceChangeType by integer only need to add the new trailing value.

  • REALIZED_PNL_IN still means a realized-PnL credit to an allocated balance.
  • REIMBURSEMENT_IN means a credit to partyAReimbursement.
  • PLATFORM_FEE_IN means released fee reserve returning to PartyA accounting.
  • DEFERRED_BALANCE_IN means deferred balance returned to PartyA allocated balance.

Code references: contracts/core/libraries/SharedEvents.sol:8-23 and contracts/core/interfaces/ISymmio.sol:52-67.
