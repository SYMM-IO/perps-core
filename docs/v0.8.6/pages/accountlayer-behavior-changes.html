AccountLayer Behavior Changes

A new aggregate affiliate read API, a reordered sub-account emptiness check that changes which error callers see, and an open-position hook that now tracks partial-fill child quotes.

Summary

Three smaller AccountLayer changes that alter what a caller observes. None of them removes surface, but each one changes data or errors that integrations already read: a new aggregate read API, a reordered emptiness check that changes which error you get, and a hook that stopped being a no-op.

Aggregate affiliate views

Reading an affiliate's configuration previously meant stitching together getAffiliateState, getAffiliateAdmin, getAffiliateFeeDistributor, getAffiliateSymmioCores, getAffiliateStakeholders, and getAffiliateSymmioShare — six calls that could observe different states if anything changed between them. v0.8.6 adds two aggregate reads. 

function getAffiliate(address affiliate) external view returns (AffiliateDetail memory);

function getAffiliateSelectorConfigs(address affiliate, bytes4[] calldata selectors)
    external view returns (AffiliateSelectorConfig[] memory);

AffiliateDetail mirrors the stored AffiliateData with the fee details flattened, and adds the affiliate's own address and its pendingFeeUpdate — which previously had no aggregate reader at all. An unregistered affiliate reads back as an empty struct with state NONE rather than reverting.

Per-selector data is not included, because hooks and both allow-lists live in mappings and cannot be enumerated from on-chain state. getAffiliateSelectorConfigs takes the selectors you care about and returns the hook address, hookAllowed, and callAllowed for each, in the order requested.

The individual getters are unchanged. These are additive; nothing that reads affiliates today needs to move.

Sub-account deletion reports the real blocker

deleteSubAccount checks that an account is empty before removing it. The order of those checks changed, and with it the error a blocked caller receives.

Balances used to be checked first, so any account with an open position or a pending quote reported SubAccountNotEmpty; trading state is now checked first and reports the actual blocker.
Order Before v0.8.6 After
1 balance / allocated balance open positions
2 open positions pending quotes
3 pending quotes balance / allocated balance

The old order could not report anything useful. An open position or a pending quote keeps its CVA and LF locked in allocated balance, and core forbids deallocating below that floor, so such an account can never be emptied first. Checking balances ahead of trading state therefore always returned SubAccountNotEmpty and pointed the caller at a withdrawal that could not succeed, instead of naming the position or quote they actually had to close.

Callers now receive OpenPositionsExist or PendingQuotesExist in those cases. SubAccountNotEmpty is still raised, but only when the account genuinely has nothing but a balance left. Error handling that branches on SubAccountNotEmpty to prompt a withdrawal needs to handle the other two.

The open-position hook now tracks partial-fill children

SymmioHookFacet.onOpenPosition was a deliberate no-op — it existed only so core would not revert when calling a hook that had nothing to do. It now does work for virtual accounts.

When a quote is partially filled, core opens the filled portion and creates a child quote carrying the remainder. That child was never registered against the virtual account, so a virtual account's quoteIds set silently lost track of the leftover inventory. The hook now reads the newest quote, checks that it is the pending child of the quote just opened and belongs to the same PartyA, and adds it to the set.

This is why the AccountLayer's view of core gained two things: getNextQuoteId became a view function so it can be called from a hook, and getQuote was added so the candidate child can be inspected before it is trusted.

Virtual account quote sets contain more entries than before. Anything that reads a virtual account's quoteIds — position accounting, UI, reconciliation — now sees partial-fill children that were previously missing. The set is more complete, not differently shaped, but a consumer that assumed one quote per position will now see two for a partially filled order.

The hook returns early for anything that is not an existing virtual account, so sub-accounts and legacy accounts are unaffected.
