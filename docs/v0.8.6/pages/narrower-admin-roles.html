Narrower Admin Roles

Roles that mixed routine operations with high-sensitivity powers are split, and every pause role is now strictly one-directional.

Summary

Several administrative roles covered functions with very different sensitivity levels. The same role that registered a new PartyB could also deregister it and slash its pledge. The same role that listed a symbol could also change its leverage and run a corporate-action restatement. A pause role could both pause and resume. v0.8.6 introduces narrower roles for the routine end of each bundle, moves a few functions to the role that matches their sensitivity, and replaces every bool-argument pause setter with a separate pause and unpause entry point.

Why

Access control is only useful when a role can be granted to the operator who needs it without also handing over powers that operator should not have. Bundled roles force one of two bad outcomes: either routine work waits on the holders of the most sensitive keys, or those keys are handed out widely because someone needs one small part of the role. Narrowing the roles lets each holder receive exactly the level of authority its job needs. It also lets an emergency responder hold a pause role outright, because pausing can no longer be turned into resuming with the same permission.

Core roles

Four roles are added to LibAccessibility. Each split is strict: the original role no longer covers the moved functions.

New role Functions it now gates What stays with the original role
PARTY_B_REGISTRAR_ROLE registerPartyB, setPartyBMetadata PARTY_B_MANAGER_ROLE keeps deregistration, solver-fee receivers, pledge withdrawal and slashing, ADL, strict deallocation, bindable, and the liquidation overshoot rate. setCrossPartyB moves here from MIGRATION_ROLE because it is per-solver configuration, not a migration step.
SYMBOL_LISTING_ROLE addSymbol, addSymbols, addSymbolsWithType, setSymbolValidationState, setSymbolTypes, setSymbolTradingFee SYMBOL_MANAGER_ROLE keeps max leverage, acceptable values, the notional liquidation-fee floor, funding state, and the whole adjustment and restatement flow.
AFFILIATE_REGISTRAR_ROLE registerAffiliate, setAffiliateMetadata AFFILIATE_MANAGER_ROLE keeps deregistration, the fee collector, and affiliate shutdown scheduling.
PROTOCOL_LIMITS_ROLE setBalanceLimitPerUser, setMaxPartyAConnectionLimit, setMaxWithdrawParts, setPendingQuotesValidLength PROTOCOL_CONFIG_ROLE keeps setLiquidatorShare and setForceClosePricePenalty, which change liquidation and force-close economics rather than operational limits.

setLegacyDeallocateDeprecated and setLegacyPartyALiquidationDeprecated are migration switches, so they now require MIGRATION_ROLE and live on PauseControlFacet next to the other deprecation switches. Their selectors are removed from ControlFacet.

Pause-only entry points

A bool-argument setter under a pause role lets the same holder both stop and resume. That defeats the purpose of a separate UNPAUSER_ROLE. The remaining two-way setters are replaced: 

// Core PauseControlFacet
// removed: setPartyBOpenPositionsPaused(address partyB, bool status)
function pausePartyBOpenPositionsFor(address partyB) external;   // PAUSER_ROLE
function unpausePartyBOpenPositionsFor(address partyB) external; // UNPAUSER_ROLE

// ExpressProvider ControlFacet
// removed: setPaused(bool value), setCreditLinePaused(address affiliate, bool paused)
function pause() external;                                // PAUSER_ROLE
function unpause() external;                              // UNPAUSER_ROLE (new)
function pauseCreditLine(address affiliate) external;     // PAUSER_ROLE or SETTER_ROLE
function unpauseCreditLine(address affiliate) external;   // SETTER_ROLE

The existing events are kept: SetPartyBOpenPositionsPausedForPartyB, PausedUpdated, and CreditLinePausedUpdated are emitted with the corresponding boolean, so indexers do not change.

ExpressProvider, InstantLayer, SymmioPartyB

  • ExpressProvider gains UNPAUSER_ROLE. Init.init grants it to the initial admin alongside PAUSER_ROLE.
  • InstantLayer gains TEMPLATE_MANAGER_ROLE, which gates addTemplate and setTemplateActive. SETTER_ROLE keeps AccountLayer routing, the target whitelist, PartyB enrollment, instant-open mode, transient context, and the revocation cooldown. The constructor grants the new role to the initial admin. InstantLayer is immutable, so this takes effect at the next redeploy.
  • SymmioPartyB gains MULTICAST_WHITELIST_ROLE, which gates setMulticastWhitelist. MANAGER_ROLE keeps ERC20 withdrawal and restricted core calls. initialize grants the new role to the initial admin. The change adds a constant only, so the UUPS storage layout is unchanged.

Upgrade notes

The facet cut on an existing core deployment replaces ControlFacet, SymbolControlFacet, and PauseControlFacet. Afterwards:

  • Grant the four new core roles to whichever accounts currently rely on the parent role for the moved functions. In particular, the AccountLayer diamond needs AFFILIATE_REGISTRAR_ROLE because affiliate approval calls registerAffiliate, and a SymmioSymbolManager needs SYMBOL_LISTING_ROLE because it proxies symbol listing and trading-fee updates.
  • Grant PARTY_B_MANAGER_ROLE to any account that calls setCrossPartyB and previously relied on MIGRATION_ROLE.
  • On an upgraded ExpressProvider, grant UNPAUSER_ROLE explicitly. Init.init does not run again, so nothing grants it during the cut.
  • Update tooling that called the removed selectors. Deployment scripts, the recipe schema, and the verification manifests in this repository already know the new names.
Role names are hashed strings. Nothing links the deployment scripts to LibAccessibility at compile time, so a new test asserts that the role list in deployAll and the verification manifest match the constants in the library.
